#153 Find Minimum in Rotated Sorted Array

Medium
Array Binary Search

題目描述

已知一個長度為 n 的陣列，預先按照升序排列，經由 1 到 n 次旋轉後，得到輸入陣列。

例如原陣列 [0,1,2,4,5,6,7] 旋轉後可能變為 [4,5,6,7,0,1,2]。

給你一個元素值互不相同的陣列 nums，請你找出並返回陣列中的最小元素。

你必須設計一個時間複雜度為 O(log n) 的演算法解決此問題。

範例

範例 1：
輸入：nums = [3,4,5,1,2]
輸出：1
範例 2：
輸入：nums = [4,5,6,7,0,1,2]
輸出：0
範例 3：
輸入：nums = [11,13,15,17]
輸出：11（旋轉了 n 次，等於沒轉）

解題思路

💡 核心：和「最右邊的元素」比較
旋轉後的陣列長這樣（兩段遞增）：

    值
     |    /|
     |   / |
     |  /  |      /|
     | /   |     / |
     |/    |    /  |
     +-----+---+---+--→ 索引
              ↑
            最小值（旋轉點）

關鍵觀察：把 nums[mid] 和 nums[right] 比較

若 nums[mid] > nums[right]：
    mid 在「左邊那段高的」，最小值一定在 mid 右側
    → left = mid + 1

若 nums[mid] < nums[right]：
    mid 在「右邊那段低的」，最小值可能就是 mid
    → right = mid（不能寫 mid - 1，會錯過答案！）

為什麼比 right 而不是比 left？

🔍 比 left 會有二義性
考慮 nums[mid] > nums[left] 的情況：

[3,4,5,1,2]  mid=5 > left=3 → mid 在左段，答案在右邊
[1,2,3,4,5]  mid=3 > left=1 → 沒旋轉，答案在左邊

同樣的條件卻導出相反的結論 → 無法判斷 ✗

改比 right 就沒有這個問題：
[3,4,5,1,2]  mid=5 > right=2 → 一定在右邊 ✓
[1,2,3,4,5]  mid=3 < right=5 → 一定在左邊（含 mid）✓

💡 這是旋轉陣列二分搜尋的通用心法：與右端點比較。

完整追蹤：nums = [4,5,6,7,0,1,2]

🔄 逐步收斂
left=0, right=6
  mid=3, nums[3]=7 > nums[6]=2 → left = 4

left=4, right=6
  mid=5, nums[5]=1 < nums[6]=2 → right = 5

left=4, right=5
  mid=4, nums[4]=0 < nums[5]=1 → right = 4

left == right == 4，結束
答案 nums[4] = 0 ✓

程式碼實現

# 二分搜尋（與右端點比較）
class Solution:
    def findMin(self, nums: List[int]) -> int:
        left, right = 0, len(nums) - 1

        while left < right:              # 注意：不是 <=
            mid = left + (right - left) // 2
            if nums[mid] > nums[right]:
                left = mid + 1           # 最小值在 mid 右側
            else:
                right = mid              # 最小值可能就是 mid
        return nums[left]                # left == right 時即答案

// 時間複雜度: O(log n)，空間複雜度: O(1)
function findMin(nums: number[]): number {
    let left = 0, right = nums.length - 1;
    while (left < right) {
        const mid = (left + right) >> 1;
        if (nums[mid] > nums[right]) left = mid + 1;   // 最小值在右半
        else right = mid;                               // mid 可能就是最小值
    }
    return nums[left];
}

        int mid = left + (right - left) / 2;
        if (nums[mid] > nums[right]) left = mid + 1;   // 最小值在右半

    }

}

複雜度分析

時間複雜度：O(log n)
  • 每次都把搜尋範圍減半
  • #154（含重複元素）最壞為 O(n)，例如 [1,1,1,1,1]
空間複雜度：O(1)

重點提示

💡 關鍵技巧 1：迴圈條件用 left < right

因為答案一定存在於區間內，收斂到 left == right 時就是答案。若寫 <= 配上 right = mid 會無限迴圈。

💡 關鍵技巧 2：right = mid 不能寫 mid - 1

因為 mid 本身可能就是最小值，減 1 會直接跳過正確答案。這與「找目標值」的二分不同，要特別注意。

💡 關鍵技巧 3：mid = left + (right-left)/2

避免 (left+right)/2 在大陣列時整數溢位。這是 Java 官方 binarySearch 曾經存在近十年的著名 bug。

⚠️ 常見錯誤：
  • 拿 nums[mid] 和 nums[left] 比較（會有二義性，無法判斷）
  • right = mid - 1 漏掉答案
  • 迴圈條件與更新方式不匹配造成無限迴圈

補充說明

二分搜尋的本質：找到「單調的判斷條件」

🎯 不是只有有序陣列才能二分
二分搜尋真正需要的不是「陣列有序」，而是：
存在一個判斷函數 check(mid)，其結果呈現
  false false false | true true true
的單調變化，我們要找的就是那個分界點。

本題的 check(mid) = 「nums[mid] <= nums[right]」
  [4,5,6,7,0,1,2]
   F F F F T T T
           ↑ 第一個 true 就是最小值

其他例子：
  #162 找峰值        check = nums[mid] > nums[mid+1]
  #875 吃香蕉速度    check = 用速度 k 能否在 h 小時內吃完
  #410 分割陣列      check = 限制最大和為 x 時能否分成 m 段

二分搜尋三種模板

【模板一】找確切值（閉區間）
while (left <= right) {
    if (nums[mid] == target) return mid;
    else if (nums[mid] < target) left = mid + 1;
    else right = mid - 1;
}
return -1;

【模板二】找左邊界 / 第一個滿足條件的（本題用這個）
while (left < right) {
    if (check(mid)) right = mid;      // mid 可能是答案，保留
    else left = mid + 1;
}
return left;

【模板三】找右邊界 / 最後一個滿足條件的
while (left < right) {
    int mid = left + (right - left + 1) / 2;   // 注意要上取整！
    if (check(mid)) left = mid;
    else right = mid - 1;
}
return left;
