#63 Unique Paths II

Medium
Dynamic Programming Matrix Array

題目描述

一個機器人位於一個 m × n 網格的左上角（起始點標記為 Start）。機器人每次只能向下或向右移動一步。機器人試圖達到網格的右下角（標記為 Finish）。

現在考慮網格中有障礙物，那麼從左上角到右下角將會有多少條不同的路徑？

網格中的障礙物和空位置分別用 1 和 0 來表示。題目保證答案小於等於 2 × 10⁹。

範例

範例 1：
輸入：obstacleGrid = [[0,0,0],[0,1,0],[0,0,0]]
輸出：2

  S 0 0
  0 X 0
  0 0 F

3×3 網格正中間有一個障礙物，共有 2 條路徑：
  1. 右 → 右 → 下 → 下
  2. 下 → 下 → 右 → 右
範例 2：
輸入：obstacleGrid = [[0,1],[0,0]]
輸出：1
範例 3：
輸入：obstacleGrid = [[1]]
輸出：0（起點就是障礙物）

解題思路

💡 狀態定義與轉移
dp[i][j] = 從起點走到 (i, j) 的不同路徑數

因為只能向右或向下走，
到達 (i,j) 的前一步只可能是 (i-1,j) 或 (i,j-1)：

  若 (i,j) 是障礙物：dp[i][j] = 0     ← 走不到，也不能經過
  否則：             dp[i][j] = dp[i-1][j] + dp[i][j-1]

這就是本題與 #62 的唯一差別：多了障礙物的判斷。

完整推導：[[0,0,0],[0,1,0],[0,0,0]]

📊 手推 DP 表格
原網格：           dp 表格：
0 0 0              1 1 1
0 X 0       →      1 0 1
0 0 0              1 1 2   ← 答案

逐格計算：
dp[0][0] = 1（起點，非障礙）
第一行：dp[0][1] = dp[0][0] = 1，dp[0][2] = 1
第一列：dp[1][0] = 1，dp[2][0] = 1

dp[1][1] = 障礙物 → 0
dp[1][2] = dp[0][2] + dp[1][1] = 1 + 0 = 1
dp[2][1] = dp[1][1] + dp[2][0] = 0 + 1 = 1
dp[2][2] = dp[1][2] + dp[2][1] = 1 + 1 = 2 ✓

答案 = 2 ✓

邊界處理的陷阱（本題重點）

⚠️ 第一行/第一列遇到障礙物後全部為 0
第一行只能一路向右走，
所以一旦遇到障礙物，它【右邊的所有格子】都到不了！

  0 0 X 0 0
  dp: 1 1 0 0 0    ← 障礙物之後全是 0，不是 1

同理第一列：一旦遇到障礙物，下面全部為 0。

❌ 錯誤寫法（照抄 #62）：
   for j in range(n): dp[0][j] = 1     ← 沒考慮障礙物！

✓ 正確寫法：
   for j in range(n):
       if grid[0][j] == 1: break        # 遇到障礙就停
       dp[0][j] = 1

💡 更好的做法：多開一行一列的「虛擬邊界」，
   讓 dp[0][*] = dp[*][0] = 0，
   再設 dp[1][1] = 1 當起點，
   這樣第一行第一列也能用統一的轉移公式，不需特判。

起點與終點也可能是障礙物

若 obstacleGrid[0][0] == 1，機器人根本無法出發，答案是 0。用上述的「虛擬邊界」寫法會自然處理這種情況。

程式碼實現

# 方法一：二維 DP，虛擬邊界（推薦，不用特判第一行列）
class Solution:
    def uniquePathsWithObstacles(self, obstacleGrid: List[List[int]]) -> int:
        m, n = len(obstacleGrid), len(obstacleGrid[0])
        # 多開一行一列當虛擬邊界，全部初始化為 0
        dp = [[0] * (n + 1) for _ in range(m + 1)]

        # 起點的「入口」設為 1（相當於從外面走進 (0,0) 有 1 種方式）
        dp[0][1] = 1

        for i in range(1, m + 1):
            for j in range(1, n + 1):
                if obstacleGrid[i - 1][j - 1] == 1:
                    dp[i][j] = 0                      # 障礙物走不到
                else:
                    dp[i][j] = dp[i - 1][j] + dp[i][j - 1]

        return dp[m][n]


# 方法二：一維滾動陣列（空間 O(n)）
class Solution:
    def uniquePathsWithObstacles(self, obstacleGrid: List[List[int]]) -> int:
        m, n = len(obstacleGrid), len(obstacleGrid[0])
        dp = [0] * n
        dp[0] = 1 if obstacleGrid[0][0] == 0 else 0

        for i in range(m):
            for j in range(n):
                if obstacleGrid[i][j] == 1:
                    dp[j] = 0                # 障礙物歸零
                elif j > 0:
                    dp[j] += dp[j - 1]       # dp[j] 是上方，dp[j-1] 是左方
                # j == 0 時 dp[0] 保持不變（只能從上方來）

        return dp[n - 1]
// 方法一：二維 DP + 虛擬邊界（推薦）
class Solution {
public:
    int uniquePathsWithObstacles(vector<vector<int>>& obstacleGrid) {
        int m = obstacleGrid.size(), n = obstacleGrid[0].size();
        // 多開一行一列，用 long long 避免溢位
        vector<vector<long long>> dp(m + 1, vector<long long>(n + 1, 0));

        dp[0][1] = 1;      // 虛擬入口

        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                if (obstacleGrid[i - 1][j - 1] == 1) {
                    dp[i][j] = 0;                       // 障礙物
                } else {
                    dp[i][j] = dp[i - 1][j] + dp[i][j - 1];
                }
            }
        }
        return (int)dp[m][n];
    }
};

class Solution {
    public int uniquePathsWithObstacles(int[][] obstacleGrid) {
        int m = obstacleGrid.length, n = obstacleGrid[0].length;
        int[] dp = new int[n];
        dp[0] = (obstacleGrid[0][0] == 0) ? 1 : 0;

        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (obstacleGrid[i][j] == 1) dp[j] = 0;
                else if (j > 0)              dp[j] += dp[j - 1];
            }

// 1D DP：障礙物格子路徑數為 0，其餘 = 上方 + 左方
// 時間複雜度: O(m·n)，空間複雜度: O(n)
function uniquePathsWithObstacles(obstacleGrid: number[][]): number {
    const n = obstacleGrid[0].length;
    const dp = new Array(n).fill(0);
    dp[0] = 1;
    for (const row of obstacleGrid) {
        for (let j = 0; j < n; j++) {
            if (row[j] === 1) dp[j] = 0;
            else if (j > 0) dp[j] += dp[j - 1];
        }
    }
    return dp[n - 1];
}
// 1D DP：障礙物格子路徑數為 0，其餘 = 上方 + 左方
// 時間複雜度: O(m·n)，空間複雜度: O(n)
int uniquePathsWithObstacles(int** obstacleGrid, int obstacleGridSize, int* obstacleGridColSize) {
    int n = obstacleGridColSize[0];
    int* dp = calloc(n, sizeof(int));
    dp[0] = 1;
    for (int i = 0; i < obstacleGridSize; i++) {
        for (int j = 0; j < n; j++) {
            if (obstacleGrid[i][j] == 1) dp[j] = 0;
            else if (j > 0) dp[j] += dp[j - 1];
        }
    }
    int ans = dp[n - 1];
    free(dp);
    return ans;
}

複雜度分析

時間複雜度：O(m × n)
  • 每個格子計算一次，每次 O(1)
空間複雜度：
  • 二維 DP：O(m × n)
  • 滾動陣列：O(n) ★
  • 也可以原地修改 obstacleGrid 達到 O(1)（但破壞輸入）

重點提示

💡 關鍵技巧 1：用「虛擬邊界」消除特判

多開一行一列讓 dp 的邊界自然為 0，配合 dp[0][1] = 1 當虛擬入口，就能讓第一行、第一列、起點是障礙物等所有情況共用同一條轉移式。這個技巧在矩陣 DP 中非常好用。

💡 關鍵技巧 2：滾動陣列的巧妙之處

在一維版本中，更新 dp[j] += dp[j-1] 時：dp[j] 還是上一行的值（代表從上方來），dp[j-1] 已經是當前行的值（代表從左方來）。剛好就是我們要的兩個方向，非常優雅。

💡 對比 #62（無障礙物）

#62 有數學解：總共要走 m-1 步下、n-1 步右，答案就是組合數 C(m+n-2, m-1)，可以 O(min(m,n)) 算出。但本題有障礙物，組合數學失效，只能用 DP。

⚠️ 常見錯誤：
  • 第一行/第一列直接全部設為 1，沒考慮障礙物後面應該是 0
  • 沒處理起點或終點就是障礙物的情況
  • 結果可能超過 int 範圍（題目保證 ≤ 2×10⁹，接近 int 上限，用 long 較保險）
  • 滾動陣列時 j == 0 忘記不加 dp[j-1]（會越界）

#62 的組合數學解法

從 (0,0) 走到 (m-1, n-1)，
總共要走 (m-1) 步「下」和 (n-1) 步「右」，共 m+n-2 步。
問題等價於：在 m+n-2 個位置中選 m-1 個放「下」

答案 = C(m+n-2, m-1)

int uniquePaths(int m, int n) {
    long long result = 1;
    // C(m+n-2, m-1)，邊乘邊除避免溢位
    for (int i = 1; i <= m - 1; i++) {
        result = result * (n - 1 + i) / i;
    }
    return (int)result;
}

O(min(m,n)) 時間，O(1) 空間 —— 比 DP 更快。
但只要加上任何限制（障礙物、必經點），
組合數學就失效，必須回到 DP。

#174 地下城遊戲：為什麼要「倒推」？

🔄 一個很有啟發性的變形
問題：騎士從左上走到右下救公主，
      每格會加血或扣血，血量歸零就死亡。
      問出發時最少需要多少血？

為什麼不能正推？
  因為「當前血量最大」不代表「後續需求最小」。
  某條路徑現在血多，但後面可能有巨大扣血；
  正推時無法判斷哪條路才是最優，違反了【無後效性】。

倒推：dp[i][j] = 從 (i,j) 出發到終點所需的【最低初始血量】
  dp[i][j] = max(1, min(dp[i+1][j], dp[i][j+1]) - dungeon[i][j])

  取 max(1, ...) 是因為血量至少要 1 才活著。

⭐ 教訓：當「正向」的狀態不滿足無後效性時，
   試試【反向】定義狀態。這是 DP 的重要思維工具。
