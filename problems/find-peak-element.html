#162 Find Peak Element

Medium
Array Binary Search

題目描述

峰值元素是指其值嚴格大於左右相鄰值的元素。

給你一個整數陣列 nums，找到峰值元素並返回其索引。陣列可能包含多個峰值，在這種情況下，返回任何一個峰值所在位置即可。

你可以假設 nums[-1] = nums[n] = -∞（陣列外側視為負無窮）。

你必須實現時間複雜度為 O(log n) 的演算法來解決此問題。

範例

範例 1：
輸入：nums = [1,2,3,1]
輸出：2
解釋：3 是峰值元素，索引為 2。
範例 2：
輸入：nums = [1,2,1,3,5,6,4]
輸出：1 或 5
解釋：索引 1（值 2）和索引 5（值 6）都是峰值，返回任一即可。

解題思路

🤔 陣列無序，為什麼還能二分？

因為題目只要求找出任意一個峰值。這讓我們可以每次都往「一定存在峰值」的那半邊走，而不需要全域有序。

核心：往上坡的方向走

💡 只比較 nums[mid] 和 nums[mid+1]
情況 A：nums[mid] < nums[mid+1]（正在上坡）

     mid mid+1
      /
     /
    ●

    右邊要嘛一直上升到最右端（因為外側是 -∞，
    最右端就是峰值），要嘛中途開始下降（那個轉折點是峰值）。
    → 右半邊【必定】存在峰值 → left = mid + 1


情況 B：nums[mid] > nums[mid+1]（正在下坡）

    ●
     \
      \
     mid mid+1

    同理，mid 自己或它左邊必定存在峰值
    → right = mid（mid 可能就是答案，不能減 1）


因為外側是 -∞，這個「往高處走一定能碰到頂」的
論證永遠成立，所以演算法必定收斂到某個峰值。

完整追蹤：nums = [1,2,1,3,5,6,4]

🔄 逐步收斂
索引:  0  1  2  3  4  5  6
值:    1  2  1  3  5  6  4

left=0, right=6
  mid=3, nums[3]=3 < nums[4]=5 → 上坡，left = 4

left=4, right=6
  mid=5, nums[5]=6 > nums[6]=4 → 下坡，right = 5

left=4, right=5
  mid=4, nums[4]=5 < nums[5]=6 → 上坡，left = 5

left == right == 5，結束
答案 5（nums[5] = 6 是峰值）✓

為什麼不用擔心 mid+1 越界？

迴圈條件是 left < right，所以 mid = (left+right)/2 向下取整後必定滿足 mid < right，也就是 mid + 1 <= right，永遠在合法範圍內。

程式碼實現

# 二分搜尋：往上坡方向走（推薦）
class Solution:
    def findPeakElement(self, nums: List[int]) -> int:
        left, right = 0, len(nums) - 1

        while left < right:
            mid = left + (right - left) // 2
            if nums[mid] < nums[mid + 1]:
                left = mid + 1          # 上坡，右半邊必有峰值
            else:
                right = mid             # 下坡，mid 可能就是峰值
        return left


# 線性掃描版本（O(n)，不符要求但可當作驗證）
class Solution:
    def findPeakElement(self, nums: List[int]) -> int:
        for i in range(len(nums) - 1):
            if nums[i] > nums[i + 1]:   # 第一個下降處就是峰值
                return i
        return len(nums) - 1            # 全程上升，最後一個是峰值
// 二分搜尋：往上坡方向走（推薦）
class Solution {
public:
    int findPeakElement(vector<int>& nums) {
        int left = 0, right = nums.size() - 1;

        while (left < right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] < nums[mid + 1]) {
                left = mid + 1;      // 上坡，右半邊必有峰值
            } else {
                right = mid;         // 下坡，mid 可能就是峰值
            }
        }
        return left;
    }
};

// 遞迴版本
class Solution {
    int search(vector<int>& nums, int left, int right) {
        if (left == right) return left;
        int mid = left + (right - left) / 2;
        if (nums[mid] < nums[mid + 1]) return search(nums, mid + 1, right);
        return search(nums, left, mid);
    }
public:
    int findPeakElement(vector<int>& nums) {
        return search(nums, 0, nums.size() - 1);
    }
};
// 二分搜尋：往上坡方向走（推薦）
class Solution {
    public int findPeakElement(int[] nums) {
        int left = 0, right = nums.length - 1;

        while (left < right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] < nums[mid + 1]) {
                left = mid + 1;      // 上坡
            } else {
                right = mid;         // 下坡
            }
        }
        return left;
    }
}

複雜度分析

時間複雜度：O(log n)
  • 每次比較後排除一半的搜尋空間
空間複雜度：O(1)（遞迴版本為 O(log n)）

重點提示

💡 關鍵技巧：二分不一定需要「全域有序」

只要能證明「某一半邊必定存在答案」，就能二分。這題是理解二分本質最好的例子，面試很愛考這個觀念。

💡 題目條件的重要性

「相鄰元素不相等」這個條件是二分成立的前提。如果允許相等（如 [1,1,1,1]），就無法判斷該往哪邊走，只能退化成 O(n) 線性掃描。面試時主動指出這點會加分。

⚠️ 常見錯誤：
  • 迴圈條件寫 left <= right，配上 right = mid 會無限迴圈
  • 寫成 right = mid - 1 會漏掉答案
  • 試圖比較 nums[mid-1]，反而要處理越界；只比 mid+1 就夠了

補充說明

延伸：二維峰值（#1901）

🔲 對「列」做二分
二維峰值定義：比上下左右四個鄰居都大

做法：對「行」做二分
1. 取中間那一行，找出該行的最大值所在的欄 c
2. 比較 mat[mid][c] 與 mat[mid+1][c]
   - 若下方較大 → 峰值在下半部
   - 否則 → 峰值在上半部（含 mid）

複雜度 O(m log n) 或 O(n log m)

正確性：該行最大值保證左右鄰居都比它小，
        所以只需要判斷上下方向。

「找任意一個」vs「找全部」的複雜度差異

  • 找任意一個峰值：O(log n)，可以二分
  • 找所有峰值：O(n)，必須檢查每個位置
  • 找最大的峰值（全域最大值）：O(n)，二分無法保證找到全域最大

面試時如果題目改成「找全域最大值」，就必須指出二分不再適用——因為往上坡走只能保證找到某個局部最大，不保證是全域最大。這是常見的陷阱追問。
