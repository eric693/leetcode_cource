#8 String to Integer (atoi)

Medium
String Simulation

題目描述

請你來實現一個 myAtoi(string s) 函數，使其能將字串轉換成一個 32 位元有號整數。

函數的演算法如下：

  1. 讀入字串並丟棄開頭的空格
  2. 檢查下一個字元是 '-' 還是 '+'，讀取該字元作為正負號；如果兩者都不存在，則預設為正數
  3. 讀入連續的數字字元，直到遇到非數字字元或到達字串結尾
  4. 將這些數字轉換成整數；如果沒有讀入任何數字，則整數為 0
  5. 如果整數超出 32 位元有號整數範圍 [-2³¹, 2³¹-1]，則截斷這個整數（-2147483648 或 2147483647）

這題考的不是演算法，而是邊界條件的嚴謹度，是韌體/系統程式面試很愛出的題目。

範例

範例 1：
輸入：s = "42"
輸出：42
範例 2：
輸入：s = " -42"
輸出：-42（前置空格被忽略）
範例 3：
輸入：s = "4193 with words"
輸出：4193（遇到空格停止）
範例 4：
輸入：s = "words and 987"
輸出：0（第一個非空格字元不是數字或符號）
範例 5：
輸入：s = "-91283472332"
輸出：-2147483648（超出下界，截斷）

解題思路

💡 四個階段循序處理
輸入 "   -42abc"

【階段 1】跳過前置空格
  i 移到 '-'

【階段 2】處理正負號（最多一個）
  sign = -1，i 移到 '4'

【階段 3】逐字讀數字並累加
  result = 0
  '4' → result = 0*10 + 4 = 4
  '2' → result = 4*10 + 2 = 42
  'a' → 非數字，停止

【階段 4】套用正負號並檢查邊界
  結果 = -42 ✓

難點：如何在不溢位的情況下檢查溢位？

🎯 在乘以 10 之前就先判斷
INT_MAX = 2147483647
INT_MIN = -2147483648

錯誤做法：先算 result = result * 10 + digit，再檢查
          → 這行本身就已經溢位了！C/C++ 中有號數溢位是 UB

正確做法：在運算「之前」預判

  若 result > INT_MAX / 10                → 一定溢位
     （因為 result * 10 必超過 INT_MAX）

  若 result == INT_MAX / 10 (= 214748364)
     且 digit > 7 (INT_MAX % 10)          → 也會溢位

範例：s = "2147483648"
  讀到 "214748364" 時 result = 214748364
  下一位 digit = 8
  result == INT_MAX/10 且 8 > 7 → 溢位 → 返回 INT_MAX ✓

負數同理。技巧：先用正數累加，
最後再套上符號，只是負數上限要多允許 1（因為 |INT_MIN| = INT_MAX + 1）。

另一個做法：用更大的型別

用 long long（C++）或 Python 的無限精度整數累加，每一步檢查是否已超出 32 位元範圍，超過就提早返回。程式碼較簡單，但在只有 32 位元的嵌入式環境中不一定可行，面試時最好兩種都能講。

程式碼實現

class Solution:
    def myAtoi(self, s: str) -> int:
        INT_MAX = 2**31 - 1        # 2147483647
        INT_MIN = -2**31           # -2147483648

        i, n = 0, len(s)

        # 階段 1：跳過前置空格
        while i < n and s[i] == ' ':
            i += 1

        # 階段 2：處理正負號
        sign = 1
        if i < n and s[i] in '+-':
            sign = -1 if s[i] == '-' else 1
            i += 1

        # 階段 3：讀數字並累加（Python 無溢位問題，但仍提早檢查）
        result = 0
        while i < n and s[i].isdigit():
            digit = int(s[i])
            result = result * 10 + digit
            # 提早截斷，避免處理超長字串
            if sign == 1 and result > INT_MAX:
                return INT_MAX
            if sign == -1 and -result < INT_MIN:
                return INT_MIN
            i += 1

        # 階段 4：套用符號
        return sign * result
class Solution {
public:
    int myAtoi(string s) {
        int i = 0, n = s.size();

        // 階段 1：跳過前置空格
        while (i < n && s[i] == ' ') i++;

        // 階段 2：處理正負號
        int sign = 1;
        if (i < n && (s[i] == '+' || s[i] == '-')) {
            sign = (s[i] == '-') ? -1 : 1;
            i++;
        }

        // 階段 3：讀數字，在運算前預判溢位
        int result = 0;
        while (i < n && isdigit(s[i])) {
            int digit = s[i] - '0';

            // 溢位檢查（在乘 10 之前！）
            if (result > INT_MAX / 10 ||
                (result == INT_MAX / 10 && digit > INT_MAX % 10)) {
                return (sign == 1) ? INT_MAX : INT_MIN;
            }

            result = result * 10 + digit;
            i++;
        }

        return sign * result;
    }
};
class Solution {
    public int myAtoi(String s) {
        int i = 0, n = s.length();

        // 階段 1：跳過前置空格
        while (i < n && s.charAt(i) == ' ') i++;

        // 階段 2：處理正負號
        int sign = 1;
        if (i < n && (s.charAt(i) == '+' || s.charAt(i) == '-')) {
            sign = (s.charAt(i) == '-') ? -1 : 1;
            i++;
        }

        // 階段 3：讀數字，在運算前預判溢位
        int result = 0;
        while (i < n && Character.isDigit(s.charAt(i))) {
            int digit = s.charAt(i) - '0';

            if (result > Integer.MAX_VALUE / 10 ||
                (result == Integer.MAX_VALUE / 10 && digit > 7)) {
                return (sign == 1) ? Integer.MAX_VALUE : Integer.MIN_VALUE;
            }

            result = result * 10 + digit;
            i++;
        }

        return sign * result;
    }
}

複雜度分析

時間複雜度：O(n)，n 為字串長度，只掃描一次
空間複雜度：O(1)，只用了幾個變數

重點提示

💡 關鍵技巧 1：溢位要「事前預判」而非「事後檢查」

在 C/C++ 中，有號整數溢位是未定義行為（UB），編譯器可以假設它不會發生並做出激進優化，所以 if (result * 10 < result) 這種事後檢查完全不可靠。必須在運算前用除法預判。

💡 關鍵技巧 2：INT_MIN 的絕對值無法用 int 表示

|-2147483648| = 2147483648 > INT_MAX，所以 -INT_MIN 會溢位。這是 32 位元二補數的經典陷阱，很多實務 bug 都源自於此。

💡 面試回答框架

這題的重點是把規格逐條翻譯成程式碼。建議先把所有邊界情況列出來（空字串、只有空格、只有符號、雙重符號、前置零、超長數字、中途出現字母），再逐一實作。展現「先釐清規格再寫程式」的習慣，比寫得快更重要。

⚠️ 邊界情況檢查清單：
  • "" 空字串 → 0
  • " " 只有空格 → 0
  • "+" / "-" 只有符號 → 0
  • "+-12" 雙重符號 → 0（讀完 '+' 後 '-' 不是數字，停止）
  • "00000123" 前置零 → 123
  • "3.14" → 3（遇到 '.' 停止）
  • " +0 123" → 0
  • "-2147483649" → -2147483648（截斷）
  • 注意題目只跳過前置空格，中間的空格會終止解析

補充說明

溢位檢查的通用模板

🛡️ 三種安全的檢查方式
【方式一】除法預判（最通用，本題使用）
  if (result > INT_MAX / 10) 溢位;
  if (result == INT_MAX / 10 && digit > INT_MAX % 10) 溢位;

【方式二】用更大的型別
  long long tmp = (long long)result * 10 + digit;
  if (tmp > INT_MAX) 溢位;
  （但 64 位元本身溢位時就沒轍了）

【方式三】編譯器內建（GCC/Clang，實務最推薦）
  int out;
  if (__builtin_mul_overflow(result, 10, &out)) 溢位;
  if (__builtin_add_overflow(out, digit, &result)) 溢位;
  → 會直接使用 CPU 的溢位旗標，最快也最安全

#7 Reverse Integer 的溢位檢查

int reverse(int x) {
    int result = 0;
    while (x != 0) {
        int digit = x % 10;
        x /= 10;
        // 完全相同的預判技巧
        if (result > INT_MAX / 10 || (result == INT_MAX / 10 && digit > 7))
            return 0;
        if (result < INT_MIN / 10 || (result == INT_MIN / 10 && digit < -8))
            return 0;
        result = result * 10 + digit;
    }
    return result;
}

實務補充：標準函式庫的做法

  • atoi()：溢位時是未定義行為，實務上不該用於處理不可信的輸入
  • strtol()：溢位時返回 LONG_MAX/LONG_MIN 並設定 errno = ERANGE，是 C 中正確的做法
  • 解析網路封包、設定檔、使用者輸入時，一律使用有錯誤回報機制的版本
