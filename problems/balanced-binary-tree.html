#110 Balanced Binary Tree

Easy
Tree DFS Binary Tree Recursion

題目描述

給定一個二元樹，判斷它是否是高度平衡的二元樹。

本題中，高度平衡二元樹定義為：一個二元樹每個節點的左右兩個子樹的高度差的絕對值不超過 1。

範例

範例 1：
輸入：root = [3,9,20,null,null,15,7]

      3
     / \
    9   20
        / \
      15   7

輸出：true
範例 2：
輸入：root = [1,2,2,3,3,null,null,4,4]

          1
         / \
        2   2
       / \
      3   3
     / \
    4   4

輸出：false
解釋：節點 1 的左子樹高 3、右子樹高 1，差 2 > 1。
範例 3：
輸入：root = []
輸出：true（空樹視為平衡）

解題思路

方法一：自頂向下（直覺但慢，O(n²)）
對每個節點：
  1. 算左子樹高度、右子樹高度，檢查差是否 <= 1
  2. 遞迴檢查左右子樹是否也都平衡

bool isBalanced(node) {
    if (!node) return true;
    if (abs(height(node->left) - height(node->right)) > 1) return false;
    return isBalanced(node->left) && isBalanced(node->right);
}

【問題】height() 被重複呼叫太多次！
根節點算一次全樹高度 O(n)，
每個子節點又各自重算…… 總計 O(n²)

方法二：自底向上（推薦，O(n)）

一趟後序遍歷同時做兩件事
讓遞迴函數「一邊算高度，一邊檢查平衡」，
用一個特殊回傳值（-1）代表「已經發現不平衡」。

int height(node) {
    if (!node) return 0;

    int left = height(node->left);
    if (left == -1) return -1;          // 左子樹已不平衡，提早返回

    int right = height(node->right);
    if (right == -1) return -1;         // 右子樹已不平衡

    if (abs(left - right) > 1) return -1;   // 當前節點不平衡

    return 1 + max(left, right);        // 平衡，回報高度
}

答案 = (height(root) != -1)

【為什麼是 O(n)？】
每個節點的高度只被計算一次，
而且一旦發現不平衡就立刻往上短路返回。

追蹤範例 2

-1 如何一路傳上去
          1
         / \
        2   2
       / \
      3   3
     / \
    4   4

height(4) = 1, height(4) = 1
height(3) = 1 + max(1,1) = 2   （左右差 0，平衡）
height(3右) = 1
height(2左)：left=2, right=1, |2-1|=1 <= 1 → 回傳 3
height(2右) = 1
height(1)：left=3, right=1, |3-1|=2 > 1 → 回傳 -1 ✗

答案 false ✓

# 方法二：自底向上（推薦，O(n)）
class Solution:
    def isBalanced(self, root: Optional[TreeNode]) -> bool:

        def height(node):
            if not node:
                return 0

            left = height(node.left)
            if left == -1:              # 左子樹已不平衡，短路
                return -1

            right = height(node.right)
            if right == -1:             # 右子樹已不平衡
                return -1

            if abs(left - right) > 1:   # 當前節點不平衡
                return -1

            return 1 + max(left, right)

        return height(root) != -1

class Solution:

            return True

        def height(node):
            if not node:
                return 0

        return self.isBalanced(root.left) and self.isBalanced(root.right)

class Solution {
    public boolean isBalanced(TreeNode root) {
        return height(root) != -1;
    }

    private int height(TreeNode node) {
        if (node == null) return 0;

        int left = height(node.left);
        if (left == -1) return -1;              // 短路

        int right = height(node.right);
        if (right == -1) return -1;

        if (Math.abs(left - right) > 1) return -1;

        return 1 + Math.max(left, right);
    }
}
/**
 * Definition for a binary tree node.
 * class TreeNode {
 *     val: number
 *     left: TreeNode | null
 *     right: TreeNode | null
 * }
 */
// 自底向上：回傳高度，不平衡時回傳 -1 提前結束
// 時間複雜度: O(n)，空間複雜度: O(h)
function isBalanced(root: TreeNode | null): boolean {
    const height = (node: TreeNode | null): number => {
        if (!node) return 0;
        const left = height(node.left);
        if (left === -1) return -1;
        const right = height(node.right);
        if (right === -1) return -1;
        if (Math.abs(left - right) > 1) return -1;
        return 1 + Math.max(left, right);
    };
    return height(root) !== -1;
}
/**
 * Definition for a binary tree node.
 * struct TreeNode {
 *     int val;
 *     struct TreeNode *left;
 *     struct TreeNode *right;
 * };
 */
// 自底向上：回傳高度，不平衡時回傳 -1 提前結束
// 時間複雜度: O(n)，空間複雜度: O(h)
static int height(struct TreeNode* node) {
    if (!node) return 0;
    int left = height(node->left);
    if (left == -1) return -1;
    int right = height(node->right);
    if (right == -1) return -1;
    if (abs(left - right) > 1) return -1;
    return 1 + (left > right ? left : right);
}

bool isBalanced(struct TreeNode* root) {
    return height(root) != -1;
}

複雜度分析

時間複雜度：
  • 自底向上：O(n)，每個節點只算一次高度 ★
  • 自頂向下：O(n²)，最壞情況（退化成鏈）高度被重複計算
空間複雜度：O(h)，遞迴堆疊，最壞 O(n)

重點提示

關鍵技巧：用特殊值當「錯誤訊號」

高度不可能是負數，所以用 -1 代表「不平衡」是安全的。這種「用不可能出現的值當旗標」的技巧能省下額外的參數或全域變數，在遞迴題中很常用。

自頂向下 vs 自底向上

凡是「上層需要下層資訊」的樹題，都應該優先考慮自底向上（後序），一趟遍歷把資訊帶上來，避免重複計算。這是把 O(n²) 優化成 O(n) 的通用手法。

常見錯誤：
  • 只檢查根節點的左右子樹高度差，忘了每個節點都要滿足
  • 發現 -1 後沒有立刻返回，繼續用 -1 參與計算導致答案錯誤
  • 把「平衡」誤解為「完全二元樹」或「所有葉子在同一層」

補充說明

為什麼「平衡」這麼重要？

平衡決定了效能
BST 的查詢複雜度是 O(h)，h 是樹高。

平衡的 BST：h = O(log n)  → 查詢快
退化成鏈：  h = O(n)      → 退化成線性搜尋 ✗

    1                    平衡：
     \                       4
      2                     /   \
       \                   2     6
        3                 / \   / \
         \               1   3 5   7
          4
    h = 4               h = 3（n=7 時 log₂7 ≈ 2.8）

依序插入 1,2,3,4... 到普通 BST 就會退化成鏈，
這就是為什麼實務上要用【自平衡樹】。

常見的自平衡樹

資料結構       平衡條件                    特點
------------------------------------------------------------------
AVL 樹        左右高度差 <= 1（本題定義）  最嚴格，查詢最快，
                                           但插入刪除旋轉次數多
紅黑樹        紅節點不相鄰、黑高相同        平衡較鬆，
                                           插入刪除較快 → 實務主流
              → C++ std::map/set、Java TreeMap、Linux CFS 排程器
B / B+ 樹     多路平衡                     為磁碟 I/O 設計，
                                           一個節點 = 一個磁碟頁
              → 資料庫索引、檔案系統
Treap / SkipList  機率平衡                 實作簡單，期望 O(log n)
              → Redis 的有序集合用 SkipList

面試延伸：如何讓一棵樹重新平衡？

  • 暴力法：中序遍歷成有序陣列，再用 #108 的方式從中點遞迴重建 → O(n)
  • AVL 旋轉：左旋、右旋、左右雙旋、右左雙旋四種操作，每次插入後回溯調整 → O(log n)
  • DSW 演算法：先把樹拉成右鏈（vine），再透過一系列旋轉壓成平衡樹 → O(n) 且 O(1) 空間
