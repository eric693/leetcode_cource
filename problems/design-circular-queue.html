#622 Design Circular Queue

Medium
Design Array Queue Linked List

題目描述

設計你的循環佇列（Circular Queue / Ring Buffer）實現。循環佇列是一種線性資料結構，其操作表現基於 FIFO（先進先出）原則，並且隊尾被連接在隊首之後以形成一個循環。

實現 MyCircularQueue 類別：

  • MyCircularQueue(k)：構造器，設置佇列長度為 k
  • enQueue(value)：向循環佇列插入一個元素，成功返回 true
  • deQueue()：從循環佇列中刪除一個元素，成功返回 true
  • Front()：從隊首取得元素，佇列為空返回 -1
  • Rear()：取得隊尾元素，佇列為空返回 -1
  • isEmpty() / isFull()：檢查是否為空 / 已滿

這是嵌入式/韌體面試出現頻率最高的設計題，因為 UART 收發、DMA 緩衝、感測器資料串流全都靠 ring buffer。

範例

範例：
MyCircularQueue q = new MyCircularQueue(3);
q.enQueue(1);   // 返回 true
q.enQueue(2);   // 返回 true
q.enQueue(3);   // 返回 true
q.enQueue(4);   // 返回 false，佇列已滿
q.Rear();       // 返回 3
q.isFull();     // 返回 true
q.deQueue();    // 返回 true
q.enQueue(4);   // 返回 true
q.Rear();       // 返回 4

解題思路

💡 核心：用取模讓索引「繞回來」
用固定大小的陣列 + 兩個索引：
  head：指向隊首元素
  tail：指向下一個要寫入的位置

索引前進時取模：index = (index + 1) % capacity

容量 3 的佇列（實際開 4 格，見下方說明）：

初始      [ _, _, _, _ ]   head=0 tail=0  空
enQueue(1)[ 1, _, _, _ ]   head=0 tail=1
enQueue(2)[ 1, 2, _, _ ]   head=0 tail=2
enQueue(3)[ 1, 2, 3, _ ]   head=0 tail=3  滿
deQueue() [ _, 2, 3, _ ]   head=1 tail=3
enQueue(4)[ _, 2, 3, 4 ]   head=1 tail=0  ← tail 繞回開頭！

關鍵難題：如何區分「空」和「滿」？

🎯 head == tail 時，到底是空還是滿？
三種常見解法：

【方法 A】多開一格（浪費一格，韌體最常用）
  陣列開 k+1 格，永遠留一格空
  空： head == tail
  滿： (tail + 1) % (k+1) == head
  優點：不需額外變數，兩個索引就能無鎖使用（單生產者單消費者）

【方法 B】額外維護 count 計數
  空： count == 0
  滿： count == capacity
  優點：不浪費空間、最好懂
  缺點：多執行緒下 count 是共享變數，需要保護

【方法 C】用 flag 標記
  維護一個 isFull 布林值，較少用

本頁 Python 用方法 B，C++/Java 用方法 A 各示範一次。

效能重點：用 & 取代 %

⚡ 容量設成 2 的冪
取模 % 在 MCU 上是很慢的除法運算。
若 capacity 是 2 的冪，可以改寫成：

  (i + 1) % capacity   →   (i + 1) & (capacity - 1)

例：capacity = 8
    7 % 8 = 7,  7 & 7 = 7  ✓
    8 % 8 = 0,  8 & 7 = 0  ✓

這就是為什麼實務上 ring buffer 大小總是 16/64/256/1024。

程式碼實現

# 方法 B：陣列 + count 計數（最好懂）
class MyCircularQueue:

    def __init__(self, k: int):
        self.capacity = k
        self.queue = [0] * k
        self.head = 0       # 隊首索引
        self.count = 0      # 目前元素個數

    def enQueue(self, value: int) -> bool:
        if self.isFull():
            return False
        # tail 由 head 和 count 推導出來
        tail = (self.head + self.count) % self.capacity
        self.queue[tail] = value
        self.count += 1
        return True

    def deQueue(self) -> bool:
        if self.isEmpty():
            return False
        self.head = (self.head + 1) % self.capacity
        self.count -= 1
        return True

    def Front(self) -> int:
        return -1 if self.isEmpty() else self.queue[self.head]

    def Rear(self) -> int:
        if self.isEmpty():
            return -1
        return self.queue[(self.head + self.count - 1) % self.capacity]

    def isEmpty(self) -> bool:
        return self.count == 0

    def isFull(self) -> bool:
        return self.count == self.capacity
// 方法 A：多開一格，不需 count（韌體標準寫法）

// 方法 A：多開一格
class MyCircularQueue {
    private int[] buf;
    private int head, tail, cap;

    public MyCircularQueue(int k) {
        cap = k + 1;            // 多開一格區分空與滿
        buf = new int[cap];
        head = tail = 0;
    }

    public boolean enQueue(int value) {
        if (isFull()) return false;
        buf[tail] = value;
        tail = (tail + 1) % cap;
        return true;
    }

    public boolean deQueue() {
        if (isEmpty()) return false;
        head = (head + 1) % cap;
        return true;
    }

    public int Front() { return isEmpty() ? -1 : buf[head]; }

    public int Rear()  { return isEmpty() ? -1 : buf[(tail - 1 + cap) % cap]; }

    public boolean isEmpty() { return head == tail; }

    public boolean isFull()  { return (tail + 1) % cap == head; }
}
// 固定大小陣列 + head 指標 + 元素個數 count
// 所有操作 O(1)，空間複雜度: O(k)
class MyCircularQueue {
    private buf: number[];
    private head = 0;
    private count = 0;

    constructor(private capacity: number) {
        this.buf = new Array(capacity);
    }

    enQueue(value: number): boolean {
        if (this.isFull()) return false;
        this.buf[(this.head + this.count) % this.capacity] = value;
        this.count++;
        return true;
    }

    deQueue(): boolean {
        if (this.isEmpty()) return false;
        this.head = (this.head + 1) % this.capacity;
        this.count--;
        return true;
    }

    Front(): number {
        return this.isEmpty() ? -1 : this.buf[this.head];
    }

    Rear(): number {
        return this.isEmpty() ? -1 : this.buf[(this.head + this.count - 1) % this.capacity];
    }

    isEmpty(): boolean {
        return this.count === 0;
    }

    isFull(): boolean {
        return this.count === this.capacity;
    }
}
// 固定大小陣列 + head 指標 + 元素個數 count（韌體 ring buffer 的經典寫法）
// 所有操作 O(1)，空間複雜度: O(k)
typedef struct {
    int* buf;
    int capacity;
    int head;
    int count;
} MyCircularQueue;

MyCircularQueue* myCircularQueueCreate(int k) {
    MyCircularQueue* q = malloc(sizeof(MyCircularQueue));
    q->buf = malloc(sizeof(int) * k);
    q->capacity = k;
    q->head = 0;
    q->count = 0;
    return q;
}

bool myCircularQueueIsEmpty(MyCircularQueue* obj) {
    return obj->count == 0;
}

bool myCircularQueueIsFull(MyCircularQueue* obj) {
    return obj->count == obj->capacity;
}

bool myCircularQueueEnQueue(MyCircularQueue* obj, int value) {
    if (myCircularQueueIsFull(obj)) return false;
    obj->buf[(obj->head + obj->count) % obj->capacity] = value;
    obj->count++;
    return true;
}

bool myCircularQueueDeQueue(MyCircularQueue* obj) {
    if (myCircularQueueIsEmpty(obj)) return false;
    obj->head = (obj->head + 1) % obj->capacity;
    obj->count--;
    return true;
}

int myCircularQueueFront(MyCircularQueue* obj) {
    return myCircularQueueIsEmpty(obj) ? -1 : obj->buf[obj->head];
}

int myCircularQueueRear(MyCircularQueue* obj) {
    if (myCircularQueueIsEmpty(obj)) return -1;
    return obj->buf[(obj->head + obj->count - 1) % obj->capacity];
}

void myCircularQueueFree(MyCircularQueue* obj) {
    free(obj->buf);
    free(obj);
}

複雜度分析

時間複雜度：所有操作都是 O(1)
  • enQueue / deQueue / Front / Rear / isEmpty / isFull 皆為常數時間
  • 這是 ring buffer 相對於一般陣列佇列（deQueue 要 O(n) 搬移）最大的優勢
空間複雜度：O(k)
  • 固定大小陣列，執行期完全不需要動態配置

重點提示

💡 關鍵技巧 1：Rear 索引要處理負數

(tail - 1 + cap) % cap，當 tail == 0 時 tail - 1 會變成 -1，加上 cap 才正確。這是本題最常見的錯誤。

💡 關鍵技巧 2：ring buffer 為什麼適合嵌入式
  • 不需動態記憶體：靜態配置，無 malloc/free，無記憶體碎片
  • O(1) 且時間可預測：符合即時系統（RTOS）的確定性要求
  • 單生產者單消費者可免鎖：ISR 寫、main loop 讀，不用關中斷
💡 面試常見追問
  • 「怎麼區分空和滿？」→ 多留一格 或 額外 count
  • 「取模很慢怎麼辦？」→ 容量設 2 的冪，用 & (size-1)
  • 「多執行緒安全嗎？」→ 單生產者單消費者且索引為原子讀寫時安全，要加 volatile 與記憶體屏障；多生產者則需要鎖或 CAS
  • 「滿了怎麼辦？」→ 丟棄新資料 / 覆蓋最舊資料（overwrite mode）/ 阻塞等待，看應用需求
⚠️ 常見錯誤：
  • 忘記多開一格，導致空與滿無法區分
  • Rear() 沒有處理 tail = 0 的負索引
  • 先更新索引再寫資料（多執行緒下會讀到未寫入的髒資料），應該先寫資料，最後才更新索引
  • ISR 中使用的索引沒宣告 volatile，被編譯器優化掉

補充說明

韌體實務：UART 接收緩衝

🔧 典型的 ISR + main loop 架構
// 中斷服務常式：收到一個 byte 就丟進 ring buffer
void USART1_IRQHandler(void) {
    if (USART1->SR & USART_SR_RXNE) {
        uint8_t data = USART1->DR;
        rb_push(&rx_buffer, data);   // 不阻塞，滿了就丟棄
    }
}

// 主迴圈：有空的時候才慢慢處理
void main_loop(void) {
    uint8_t byte;
    while (rb_pop(&rx_buffer, &byte)) {
        parse_protocol(byte);
    }
}

好處：ISR 極短（只做搬資料），不會拖慢中斷回應時間，
      解耦「資料到達的速度」與「處理的速度」。

三種佇列實作比較

實作方式            enQueue   deQueue   記憶體      適用場景
-----------------------------------------------------------------
一般陣列 + 搬移      O(1)      O(n)     連續        小資料量
動態陣列（vector）   攤銷O(1)  O(n)     連續、會擴  一般應用
鏈結串列             O(1)      O(1)     分散、有額外指標  容量不固定
環形緩衝（本題）     O(1)      O(1)     連續、固定  嵌入式、即時系統 ★

延伸：覆蓋模式（Overwrite Mode）

某些應用（如飛行記錄器、示波器取樣）希望永遠保留「最新的 N 筆」，滿的時候不是拒絕寫入，而是覆蓋最舊的資料：

void rb_push_overwrite(ring_buffer_t *rb, uint8_t v) {
    rb->buf[rb->tail] = v;
    rb->tail = (rb->tail + 1) & RB_MASK;
    if (rb->tail == rb->head)                  // 滿了就推進 head
        rb->head = (rb->head + 1) & RB_MASK;   // 丟掉最舊的一筆
}
