#235 Lowest Common Ancestor of a Binary Search Tree

Medium
Tree Binary Search Tree DFS

題目描述

給定一個二元搜尋樹，找到該樹中兩個指定節點的最近公共祖先（LCA）。

最近公共祖先的定義：對於有根樹 T 的兩個節點 p、q，最近公共祖先表示為一個節點 x，滿足 x 是 p、q 的祖先且 x 的深度盡可能大（一個節點也可以是它自己的祖先）。

與 #236 的差別在於：這裡是 BST，可以利用「左小右大」的性質大幅簡化。

範例

範例 1：
        6
       / \
      2   8
     / \ / \
    0  4 7  9
      / \
     3   5

輸入：p = 2, q = 8
輸出：6
範例 2：
輸入：（同上樹）p = 2, q = 4
輸出：2
解釋：節點 2 是節點 4 的祖先，也是自己的祖先。

解題思路

💡 核心：LCA 就是「值的分岔點」
BST 性質：左子樹全部 < 根 < 右子樹全部

從根開始，比較 p、q 的值與當前節點：

情況 1：p.val < root.val 且 q.val < root.val
        → 兩者都在左子樹 → 往左走

情況 2：p.val > root.val 且 q.val > root.val
        → 兩者都在右子樹 → 往右走

情況 3：其他（一大一小，或其中一個等於 root）
        → 這裡就是【分岔點】= LCA ✓

因為再往下走任何一邊，都會把另一個節點排除掉。

完整追蹤：p = 2, q = 8

🔄 一路往下直到分岔
        6
       / \
      2   8

root = 6：
  p=2 < 6，q=8 > 6 → 一大一小，分岔！
  返回 6 ✓

再看 p = 2, q = 4：
root = 6：
  p=2 < 6，q=4 < 6 → 都在左邊，往左走
root = 2：
  p=2 == 2 → 命中其中一個，返回 2 ✓
  （因為 2 是自己的祖先，且 4 在它的子樹裡）

與 #236 的效能差異

📊 為什麼 BST 版本更快
              #236 普通二元樹      #235 BST
-------------------------------------------------
判斷依據      要走訪整棵樹找節點   直接用值的大小關係
時間          O(n)                 O(h) = O(log n) 平衡時
空間          O(h) 遞迴堆疊        O(1)（可寫成迭代）★
走訪範圍      最壞每個節點都要看   只走一條根到節點的路徑

BST 版本只需要走「一條路徑」，
完全不用進入不相關的子樹，效率好非常多。

程式碼實現

# 迭代版（推薦，O(1) 空間）
class Solution:
    def lowestCommonAncestor(self, root: 'TreeNode', p: 'TreeNode', q: 'TreeNode') -> 'TreeNode':
        cur = root
        while cur:
            if p.val < cur.val and q.val < cur.val:
                cur = cur.left       # 兩者都在左子樹
            elif p.val > cur.val and q.val > cur.val:
                cur = cur.right      # 兩者都在右子樹
            else:
                return cur           # 分岔點就是 LCA
        return None


# 遞迴版
class Solution:
    def lowestCommonAncestor(self, root, p, q):
        if p.val < root.val and q.val < root.val:
            return self.lowestCommonAncestor(root.left, p, q)
        if p.val > root.val and q.val > root.val:
            return self.lowestCommonAncestor(root.right, p, q)
        return root

                cur = cur->right;     // 兩者都在右子樹
            } else {
                return cur;           // 分岔點就是 LCA
            }

        return nullptr;
    }
};

class Solution {
    public TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) {
        TreeNode cur = root;
        while (cur != null) {
            if (p.val < cur.val && q.val < cur.val) {
                cur = cur.left;       // 兩者都在左子樹
            } else if (p.val > cur.val && q.val > cur.val) {
                cur = cur.right;      // 兩者都在右子樹
            } else {
                return cur;           // 分岔點就是 LCA
            }
        }
        return null;
    }
}

複雜度分析

時間複雜度：O(h)
  • h 為樹高；平衡 BST 時為 O(log n)
  • 最壞（退化成鏈）為 O(n)
  • 只走一條路徑，不需要走訪整棵樹
空間複雜度：
  • 迭代版：O(1) ★
  • 遞迴版：O(h) 的呼叫堆疊

重點提示

💡 關鍵技巧：看到 BST 就先想「能不能利用大小關係」

BST 題目的通用心法：把「搜尋」問題變成「往左還是往右」的判斷。這能把 O(n) 的走訪降到 O(h)。#98 驗證 BST、#230 第 k 小、#700 搜尋、#701 插入都是同樣的思路。

💡 為什麼「分岔點」一定是 LCA？

假設 p.val <= root.val <= q.val。若再往左走，新的節點值會小於 root，q 就不可能在它的子樹裡；往右走則 p 被排除。所以 root 是最後一個能同時包含兩者的節點，正是最近公共祖先。

⚠️ 常見錯誤：
  • 沒有處理「p 或 q 就是當前節點」的情況（本解法的 else 分支自動涵蓋了）
  • 條件寫成 <=，會在 p == root 時繼續往下走而錯過答案
  • 直接套用 #236 的解法（雖然正確，但浪費了 BST 的性質，面試會被扣分）

BST 的核心性質總整理

1【中序遍歷 = 遞增序列】
   → #98 驗證、#230 第 k 小、#530 最小絕對差、#173 迭代器

2【搜尋只走一條路徑，O(h)】

3【左子樹全部 < 根 < 右子樹全部】（是「全部」，不只是直接子節點！）
   → #98 驗證時必須傳遞上下界，只比較父子是不夠的

4【最小值 = 一路往左；最大值 = 一路往右】
   → #450 刪除節點時用來找後繼節點

5【範圍查詢可剪枝】
   → #938 區間和：若 root.val < low 就完全不用進左子樹

#98 驗證 BST 的常見陷阱

❌ 錯誤：只比較父子關係
    if (node->left && node->left->val >= node->val) return false;

  反例：      5
             /             1   6
               /               3   7      ← 3 < 5 卻在右子樹！局部檢查會漏掉

✓ 正確：傳遞上下界
bool validate(TreeNode* node, long lo, long hi) {
    if (!node) return true;
    if (node->val <= lo || node->val >= hi) return false;
    return validate(node->left,  lo, node->val)
        && validate(node->right, node->val, hi);
}
// 初始呼叫：validate(root, LONG_MIN, LONG_MAX)

✓ 或者：中序遍歷檢查是否嚴格遞增

面試延伸問題

  • 「如果 p 或 q 不一定存在於樹中呢？」→ 需要額外驗證兩者是否都存在，否則答案無意義
  • 「如果樹很大且查詢很多次？」→ 可以預處理成倍增表（Binary Lifting）達到 O(log n) 查詢
  • 「如果 BST 允許重複值？」→ 需要明確定義重複值放左邊還是右邊，並調整比較的等號
